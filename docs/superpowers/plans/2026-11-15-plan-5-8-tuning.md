# Plan 5.8: Account tuning moves to Stronghold

Branch: `refactor/stronghold-tuning`.

## What moved

1. Stronghold `src/tuning/`: an account's own response limits (`max_output_tokens`, `max_tool_rounds`, Treasury collection `tuning_limits`, key the account uid) and the routes `GET|PUT|DELETE /tuning/limits`, `GET /tuning/limits/own` (only the stored values) and `DELETE /tuning/accounts/{uid}`.
2. Stronghold reads Legion's current tuning itself (`LegionTuning`, `GET /agents/tuning` on the entry agent, else any running one, found through its own agent directory). That value is the cap: saving is refused (502) while Legion cannot be asked.
3. Portcullis `/api/account/tuning` now only checks the login and passes the request on.
4. When a chat turn starts, Portcullis asks `GET /tuning/limits/own`. Stronghold down, or a bad answer, means no personal limits: the turn runs on the administrator's values, as it did when storage failed before.
5. Account delete purges the limits through Stronghold (`admin.tuning_purge` on failure). Portcullis's `tuning_limits_service.py` is gone.

## What did not move

`/api/admin/tuning` (the administrator's tuning of Legion itself, `tuning.manage`) stays in Portcullis: it is Legion administration, which moves with the admin app split (Plan 7).

## Accepted behavior changes

1. Personal limits saved before this plan are not copied: they live in Portcullis's own database and start empty. Everyone runs on the administrator's values until they save new ones.
2. Reading and saving personal limits now needs Stronghold (502 when it is down). Starting a chat turn does not: it just runs without them.
