# Ember Web component redundancy audit

Date: 2026-10-22. Scope: all 107 Vue files (85 components, 21 views, one app shell). No application code was changed by this audit.

Production references were parsed with TypeScript and the Vue SFC parser, then traced from `src/main.ts` through static and lazy imports. Tests were excluded from production reachability and checked separately. Type-only consumers and Admin consumers were checked separately. There is no global component registration or component-import glob in the current Web source. Similarity screening and targeted source comparisons informed the consolidation findings; reachability is not proof that an active file has no internal duplication.

97 files are runtime-reachable. Ten renderers are not, representing 1359 source lines. Eight are straightforward unused-code candidates, one needs a type extraction, and one has an explicit compatibility purpose. Unit tests for an otherwise unused component do not make it production-reachable.

## Active duplication worth consolidating

1. **Dialog shell/lifecycle:** `components/tools/forms/CommandFormModal.vue` (watch at line 18, dialog at line 34), `features/chat/components/ShareDialog.vue` (line 61/116), and `features/chat/components/TemplatesModal.vue` (line 43/95) repeat native-dialog state, headers, close controls, and shell styling already supplied by `components/ui/dialogs/BaseModal.vue`. Keep their domain workflows and reuse the shell. Templates has special Escape-to-list behavior, and sharing has secret reset/invalidation rules; the current BaseModal close policy must be reconciled explicitly rather than replacing markup mechanically.

2. **Clipboard behavior:** `components/tools/ToolResultPanel.vue:25` and `components/tools/gui/GuiResult.vue:24` each implement their own copied state, direct clipboard write, and 1500 ms timer. Reuse `components/ui/buttons/CopyButton.vue`, which already provides the fallback, failure feedback, and timer cleanup. Preserve the current raw JSON/secret copy payloads and result-specific layout.

3. **Duplicate type declaration:** `CapabilityCard.vue:9` and `CapabilitySection.vue:7` both declare `SectionPage`. Only the section declaration is used by the active workspace. Move the surviving contract into the capabilities feature’s types before removing either retired renderer.

## Similar-looking components to retain

- `ActionButton`, `CopyButton`, `DeleteButton`, and `SaveButton` have different state, interaction, and accessibility contracts. Share styling selectively; do not collapse them into a flag-heavy universal button.
- `CommandFormModal` produces chat command text; `ToolRunModal` runs a tool directly. Both correctly reuse `ToolRunForm`; consolidate their modal shell, not their workflows.
- `GuiResult` interprets server-defined secret/table/message presentation; `ToolResultPanel` renders generic JSON/Markdown. Share clipboard behavior rather than merging the renderers.
- `CountdownRing` counts down a supplied remaining/total value; `ElapsedTime` owns a running elapsed clock.
- `TemplatePicker` selects prompts; `TemplatesModal` manages them. `ChatRow` is a conversation; `ChatSection` is a grouping/drop target.
- Small modules such as `PageLayout`, `AuthCard`, and `ElapsedTime` centralize layout or lifecycle behavior and are not redundant merely because their templates are short.

Admin maintains separate shared-component copies by project convention. In particular its `LockSwitch` and `IntegrationToolsModal` are live, so this report does not recommend removing those Admin files. Package-level sharing between the apps would be a separate change.
