# Plan 5.9: Chats, folders and search move to Stronghold

Branch: `refactor/stronghold-chats`.

## What moved

1. Stronghold `src/chats/`: chat storage in Treasury, in three collections keyed `<owner uid>:<id>`: `chats` (title, agent, folder, pin, second-brain settings, times), `chat_messages` (the transcript, kept apart so the sidebar list never reads one) and `chat_folders`. Routes: `GET|DELETE /chats`, `GET /chats/search`, `GET|PUT|PATCH|DELETE /chats/{id}`, `PUT /chats/{id}/messages`, `POST /chats/{id}/branch`, `DELETE /chats/accounts/{uid}`, and `GET|POST /chat-folders`, `PATCH|DELETE /chat-folders/{id}`.
2. The rules came with it: 2 MB per chat, 1000 chats and 30 folders per account, folder names unique ignoring case, a branch ends on a plain answer, search by title and message text (attachment bodies skipped, at most 50 hits, newest first). Folder changes are logged by Stronghold (`chat_folder.*`).
3. Deleting a chat, all chats or a folder revokes the share links inside Stronghold, in the same call, before anything is deleted. Portcullis no longer calls `/shares/revoke` (`revoke_shares` is gone; the route stays in Stronghold, unused).
4. Portcullis keeps the turn engine (asking the agent, approvals, questions, summarize, suggestions, second brain, usage checks) and the in-memory list of running turns. It reaches chats through `ChatService`, a client with the same calls as before (`get`, `put`, `replace_messages`, `update`, `branch`, `delete`...) that asks Stronghold. The turn engine saves the question and the answer there.
5. `GET /api/chats/search` and `/api/chat-folders` are passed on. Deleting a folder sends Stronghold the list of this account's chats that have an answer being written, so a live answer is never cut off. Account delete purges chats and folders through Stronghold (`admin.chats_purge` on failure).
6. Removed from Portcullis: `services/chat_search.py`, `services/folder_service.py`, `revoke_shares`. Their tests moved to Stronghold (`tests/test_chats.py`). Portcullis tests run against `tests/fake_chats.py`, a small stand-in for Stronghold's chat routes.

## What did not move

1. The turn engine and the running-turn registry (`services/turns.py`): they need the agents, approvals and live streaming. Moving them is a later step.
2. The legacy `services/chat_app_import.py` (a one-off import from the old chat_app) still writes the old `chats` SQL table, which nothing reads now. It is stale already (it also writes token usage into SQL); retire it when Plan 6 is done.
3. The old `chats` and `chat_folders` SQL tables stay in Portcullis's database, unused.

## Accepted behavior changes

1. **Every chat, folder and pin starts empty.** No data migration (as decided for Plan 5): existing history stays in the old SQL tables, unreachable. Back up Portcullis's database first if the old chats matter.
2. Folder ids and share link ids are random numbers up to 2^31 now, not a counting sequence.
3. Chats, folders, search, branching and every question need Stronghold running (502 `Stronghold is unavailable` otherwise). Before, Stronghold was needed for the extras only.
4. Deleting is not one database transaction any more: if Stronghold fails halfway through a folder or "delete all", some chats can be gone and the call answers 5xx. Share links are always revoked first.
5. Two sessions saving the same chat at the same moment can overwrite each other (Treasury has no transactions). Turns save one at a time per chat, and the browser cannot save while an answer is running.
6. A chat's two documents (details and transcript) are written one after the other; a crash between them can leave a changed transcript with the old details.
