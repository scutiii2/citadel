# Plan 5.6: Usage moves to Stronghold

Branch: `refactor/stronghold-usage`. Chosen first because tickets/triage and brains need usage accounting.

## What moved

1. Stronghold `src/usage/`: settings (limits, pricing), the service (record, check, windows, report, records, all accounts, purge) and `/usage` routes. Rows are documents in Treasury collection `usage_records`, one per agent call, key `<uid>:<random>`.
2. Portcullis `/api/usage` and `/api/admin/usage...` pass the request on. The administrators' list asks `GET /usage/all` and adds every account (zero for those without usage). Viewing another account's usage forwards the call with that account as the requester.
3. Portcullis `services/usage_client.py`: `check()` before and `record()` after every chat turn, summary, suggestion, triage question and brain review. `UsageClient(stronghold, account)`.
4. `services/usage_rows.py` (kept in Portcullis): reads the per-agent rows out of an agent's answer. Turns still show them per message; `stored_rows()` strips display-only keys and sends the rest to Stronghold.
5. Account delete purges the account's usage rows through Stronghold (`DELETE /usage/accounts/{uid}`, best effort, `admin.usage_purge`).
6. Config: `usage.six_hour_token_limit` / `weekly_token_limit` and the `pricing` block are Stronghold's (`config_app.json`). Portcullis keeps `usage.max_context_tokens_per_chat` / `auto_summarize_ratio` and `config_pricing.json` (chat messages still show their cost).

## Accepted behavior changes

1. History starts empty: no migration, as decided. Everyone's 6-hour and weekly windows start at zero, and the Usage page shows only new usage. The old `usage_records` table stays in Portcullis's database, unused.
2. A check that cannot be answered refuses the turn, summary, triage question or brain review with `503` `Usage is unavailable` (Stronghold or Treasury down). A suggestion is skipped instead. Reason: without the answer a limit cannot be kept.
3. A record that cannot be stored is logged (a warning without the uid) and dropped; the user still gets the answer. Before, a database error could fail the call.
4. Row ids on the Usage page are random numbers now, not a counting sequence.
5. Limits are measured in UTC days of rows: a check reads up to 8 days of an account's rows. Fine for hundreds of rows a day; add per-hour sums if that grows (marked `shortcut:` in `usage/service.py`).
6. Pricing exists twice until chats move (5.9): Stronghold's `pricing` block for the Usage page, Portcullis's `config_pricing.json` for costs on chat messages. Change both.
7. The one-off chat_app importer (`scripts/import_chat_app.py`) still writes usage into Portcullis's old table, so imported usage no longer shows on the Usage page.
8. A local `configs/config_app.json` in Portcullis that sets the token limits needs them copied into Stronghold's `config_app.json`; the old keys are ignored.
